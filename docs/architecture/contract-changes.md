# Contract changes

Breaking changes to `opdf-core`, newest first. Additive changes are not
recorded here.

| Date | Change | Rationale | Landed in |
| --- | --- | --- | --- |
| 2026-08-17 | **Document identity, batched with three other breaking changes.** `Document` gains `fn id(&self) -> DocumentId` (**no default body**) plus the object-safe pair `fn export_pages(&self, ids: &[PageId]) -> Result<PortablePages>` / `fn import_portable(&mut self, pages: PortablePages, at_index: usize) -> Result<Vec<PageId>>`; `DocumentSnapshot` gains a `document` field, captured by `of`; `RenderRequest` gains a `document` field, taken as the first argument of `new(document, page, revision, scale)`, included in `PartialEq`/`Eq`/`Hash`, and the struct becomes `#[non_exhaustive]`; `Error` gains `RollbackFailed { original, rollback }`; `Command<D>`'s bound relaxes to `D: Document + ?Sized` | Four sessions independently hit the same missing primitive and each shipped a different workaround, so `opdf-core` was opened exactly once for all of them. **(1)** `opdf-ops/src/binding.rs` identified a document *by its memory address* (`std::ptr`), sound only because a cross-document call borrows both at once — moving the document broke every binding taken before the move. Gone; `DocumentBinding` now wraps a `DocumentId`. **(2)** `opdf-app` minted its own process-local `DocumentId` from an `AtomicU64` in `viewer.rs`, invisible to the renderer, so the only thing it could do with it was empty every cache. Gone; the shell reads the core identity off the snapshot and it is the same value the renderer keys on. **(3)** An unclaimed render response was filed into `caches[0]`; two documents both start at revision 0 with page ids from 0, so a late response from A could be stored as a B tile — safe *only* while "new document ⇒ new service, old dropped" held, a convention nothing enforced. Now rejected by key. **(4)** A composed rollback failure was squeezed into `Error::Unsupported(String)` because no compound variant existed, so the caller could not distinguish "your command failed" from "your command failed AND the document is now inconsistent". Folded in while the world was stopped: `import_pages` was excluded from the vtable by `where Self: Sized`, blocking cross-document drag (a named M2 feature) — **decided in favour of the additive `export_pages`/`import_portable` pair over making `import_pages` object-safe**, because an object-safe `import_pages` taking `&dyn Document` cannot reach the source's concrete representation and would have destroyed `opdf-pdf`'s object-graph copy, the one thing its importer does well; `import_pages` is untouched and remains the fast path, the pair costs a copy. And `Command<D>` carried an implicit `Sized` bound, so `Command<dyn Document>` and `UndoStack<dyn Document>` were unnameable and a shell owning a `Box<dyn Document>` could hold the document but no history over it; relaxing it is additive and rippled nowhere. `DocumentId::new_unique` never reuses an identity; `PdfDocument::rebase_onto` (compaction) **keeps** the existing identity — the same open document, rewritten. `Document::id` has no default body deliberately: a default would let an implementation share one identity across every instance, which is the exact defect this prevents. A foreign `PortablePages` must fail with `Error::Unsupported`, asserted in the contract suite in both directions rather than left to each implementation. **Every session must rebase before continuing.** | `feat/document-identity`, `98f9c8a..2b0a334` — 39 commits, one file each. `9617f4a` the `DocumentId` type and trait method, `8785baf` the identity contract assertion, `18e8bf5` the `opdf-ops` address workaround removed, `7df334d` `RenderRequest`, `ca9a391` the render contract assertions, `b4ed168` `DocumentSnapshot`, `a1b956d` the `opdf-app` workaround removed, `6a36228` `Error::RollbackFailed`, `1b89d2c` `PortablePages`, `65583b4` the portable contract assertions, plus this entry. Baseline 529 tests → 539, all green under `cargo fmt --all --check && cargo clippy --all-targets --all-features -- -D warnings && cargo test --all --all-features` |
| 2026-08-13 | `Document` gains `fn restore_page(&mut self, id: PageId, at_index: usize) -> Result<()>`, and with it a trash model: a removed page is retained by the document, unreferenced, until an explicit compaction purges it | Undo of a page deletion could not restore the page. `remove_page` destroyed it and `insert_page` only ever creates a *blank* page under a *fresh* `PageId`, so deleting page 3 and undoing gave an empty page with a new identity — and split and delete-selection inherited the defect. A restored page now comes back with its original identity, geometry, and rotation; restoring a live page is `Error::Unsupported`, not a no-op; `at_index == page_count()` is a valid append, so deleting a last page can be undone. The trash mirrors PDF incremental save, which never deletes an object and only unreferences it, and avoids making `opdf-core` model page content so a command's inverse could carry it. Four of the five tracks build on this trait, so adding it afterwards would break the one crate they all depend on. | Phase 0, `17ee4c9..ca1704c` — `5b5e3a1` the contract and `VecDocument`, `2fcea3f` the contract suite, `ca1704c` the reference, plus this entry |
| 2026-08-13 | `Document` gains `fn revision(&self) -> u64`; `DocumentSnapshot` gains a `revision` field, captured by `of`; `RenderRequest` gains a `revision` field, taken explicitly by `new(page, revision, scale)` and included in `PartialEq`/`Eq`/`Hash` | Nothing in a render request identified document state, so after `set_rotation(page_3, Quarter)` a tile cached for the byte-identical `RenderRequest` was stale and the canvas kept showing the old orientation. Every mutation must now advance the revision on success and leave it untouched on failure; the renderer carries and echoes the revision but never validates it. `new` takes it positionally rather than defaulting it, because a caller who forgets it silently reintroduces the same stale-tile bug. Adding this after the tracks start would break the one crate all five depend on. | Phase 0, `ab507f4..fc59548` — `ddfcae3` the contract, `fc59548` the reference, plus this entry |
| 2026-08-13 | `Command<D>` gains `Send` as a supertrait | The render worker owns the document, so commands and the undo stack of `Box<dyn Command<D>>` inverses cross threads. Adding the bound after Track C starts would invalidate every command written in the meantime. | Phase 0 |
| 2026-08-13 | `RenderRequest` implements `Eq` and `Hash`; `PartialEq` becomes a manual impl comparing `scale` bitwise | A tile cache and the UI's tile map both need `RenderRequest` as a key. Without this each track invents its own quantised-scale key, and those keys disagree at integration. `Rotation` gains a derived `Hash` to support it. | Phase 0 |
